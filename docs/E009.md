# E009: frozen WavLM audio embeddings + Ridge

Research question: does original audio contain grammar-scoring information absent
from the canonical Whisper transcript? This implementation does not read transcripts.
E005/E008 code and behavior are unchanged. GPU extraction and E009 metrics are pending.

The canonical train CSV and existing E005 folds must contain 769 matching rows.
Filtering uses only `label > 0.0`, retaining 732 and removing 37. Folds are never
regenerated. Original mono PCM16 16-kHz WAV files use the existing waveform loader.
Every recording is split into sequential non-overlapping 320,000-sample chunks,
including its shorter tail. A tail smaller than the convolution receptive field
merges into the preceding chunk, preserving every original sample exactly once.
The minimum size is derived from the model convolution kernels and strides
(400 samples for wavlm-base-plus). No truncation, augmentation or silence filtering
occurs.

The frozen `microsoft/wavlm-base-plus` encoder runs float32, eval and no_grad.
Its canonical Hugging Face feature extractor normalizes each chunk. Equal-length
chunks batch together and shorter tails run separately, avoiding padding effects
in the encoder as well as pooling. Valid hidden-frame lengths come from the model's
convolution length helper. Final hidden states are masked before temporal averaging;
utterance means weight each chunk by its original sample count (valid duration).
An entire recording shorter than the receptive field has no valid hidden frame
and raises explicitly; a pathological final tail instead merges as described above.
Chunk-count validation uses the same sample-based plan, including merged tails.
The Kaggle smoke chooses three complete recordings by duration: <20 seconds,
20-40 seconds (inclusive), and >40 seconds. Missing buckets are reported explicitly
and replaced by distinct recordings maximizing duration coverage. Smoke reports
original durations/sample counts, chunk sample counts, valid hidden-frame counts,
embedding dimension/finite status, batch-size invariance, model/revision, sample
rate, target chunk duration, device/dtype, chunk batch size and peak CUDA allocated
memory (bytes; null on CPU).

Each fold fits its own StandardScaler and Ridge(alpha=1.0) using only training
rows, then predicts that fold's validation rows once. Predictions are raw continuous
values. There is no search, calibration, clipping, test inference or submission.
Without `--e008-oof`, E009 reports its own pooled/per-fold metrics and records
`e008_comparison_status="not_run"`, `e008_oof_path=null`; no E008 metrics are
produced. Smoke never loads E008 OOF, even if the option is supplied.
When `--e008-oof` is supplied, the E008 comparison validates exact filename, label and fold identity before
reporting pooled/per-fold RMSE and Pearson, E009-minus-E008 deltas, prediction
correlation and residual correlation (`label - prediction`). Undefined correlations
serialize as JSON null via the existing project JSON helper.

Artifacts under the chosen root:

- `embeddings/E009/train_embeddings.npy`: finite 732-by-768 matrix.
- `embeddings/E009/train_metadata.csv`: ordered filename, label, fold,
  duration_seconds, num_chunks.
- `embeddings/E009/extraction.json`: source WAV hashes, population identity,
  model/revision, pooling, sample rate, chunk duration, dimension, seed, dtype,
  dependency versions and cache checksums.
- `oof/E009_wavlm_ridge.csv`: filename, label, fold, prediction, residual, abs_error.
- `experiments/E009/diagnostics.json`: E009 pooled/per-fold diagnostics and
  optional paired E008 comparison.

Existing complete compatible embeddings are reused without encoder inference.
Incompatible or modified caches fail; partial caches raise
`ValueError("Incomplete E009 extraction cache")`. There is no overwrite switch.
Keep generated artifacts out of git. Optional `--revision` pins the Hugging Face
revision; the resolved commit is recorded and used to load the extractor.
The default seed is 42; deterministic Torch algorithms are enabled.

Kaggle prerequisites: GPU enabled, CUDA PyTorch compatible with installed NumPy,
Transformers, and the project's scientific dependencies. These reuse optional ML
packages already used by E005; no project dependency changes are needed.
Install the repository with `pip install --no-deps -e /kaggle/working/grammar-scoring`.
Place competition data under `Dataset_Final` and mount canonical folds.
E008 OOF is optional for full runs. The reusable `compare_oof(oof, baseline, retained)`
function accepts saved predictions for later comparison without encoder execution.
Replace the input mount names below with your dataset names.

Smoke test (isolated summary; no canonical embeddings or OOF outputs):

```sh
GRAMMAR_DATA_DIR=/kaggle/input/your-competition-data \
python /kaggle/working/grammar-scoring/scripts/run_wavlm_ridge.py \
  --fold-path /kaggle/input/your-canonical-artifacts/features/train_folds.csv \
  --artifact-dir /kaggle/working/artifacts --device cuda --chunk-batch-size 4 --smoke
```

Full extraction followed by fixed Ridge CV and diagnostics (rerunning reuses cache):

```sh
GRAMMAR_DATA_DIR=/kaggle/input/your-competition-data \
python /kaggle/working/grammar-scoring/scripts/run_wavlm_ridge.py \
  --fold-path /kaggle/input/your-canonical-artifacts/features/train_folds.csv \
  --artifact-dir /kaggle/working/artifacts --device cuda --chunk-batch-size 4
```

To include the comparison in a full run, add
`--e008-oof /kaggle/input/your-e008-artifacts/oof/E008_deberta_no_zero_block.csv`.
A supplied missing file or misaligned baseline fails before encoder construction.

Feature extraction follows the [Hugging Face WavLM documentation](https://huggingface.co/docs/transformers/model_doc/wavlm).
