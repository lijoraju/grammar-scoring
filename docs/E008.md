# E008: DeBERTa without the zero-label block

Does excluding the anomalous zero-label training block improve the exact E005
model on the ordinary/test-relevant population? This is a controlled population
ablation: E005 fits all 769 examples; E008 fits only the 732 with `label > 0.0`.

Exploratory analysis motivating this experiment identified 37 zero-label rows
(4.81%), the contiguous audio_5037.wav–audio_5073.wav block. They reportedly
contributed 43.22% of E005 OOF squared error. Sampled recordings contained heavy
background noise with strong English faithfully represented by Whisper.
These are supplied motivating observations, not E008 results. Filename IDs are
diagnostic evidence only: the filter uses labels exclusively, and neither
filenames nor audio IDs enter the model or any prediction-time rule.

The existing canonical E005 loader first validates all 769 training rows, raw
Whisper large-v3 transcripts and frozen folds. E008 then removes exactly 37 rows,
retains exactly 732, checks folds 0..4 and verifies each retained assignment
against the original artifact. No folds are regenerated. Each fold trains on
retained rows outside that fold and validates only retained rows inside it.
Zero-label rows appear in neither partition. Transcript text remains unchanged.

## Frozen training protocol

E008 calls the same fold training, checkpoint selection, recovery validation,
and OOF assembly as E005. It does not mutate E005's configuration.

- Fully trainable `microsoft/deberta-v3-base` AutoModel, final hidden state,
  attention-mask-aware mean pooling, dropout 0.1, Linear(hidden_size, 1).
- Continuous regression with MSE; max_length 256, truncation, dynamic padding.
- AdamW, learning rate 2e-5, weight decay 0.01, batch size 8, accumulation 2
  (effective batch 16), all five epochs, seed 42.
- Linear scheduler, warmup ratio 0.10 (same E005 ceil step calculation),
  max gradient norm 1.0, CUDA FP16 with float32 parameter storage.
- Validation after every epoch; minimum validation RMSE independently per fold;
  first epoch wins exact ties, with no patience stopping.
- Raw continuous predictions with no clipping, calibration or rounding.

Pretrained revision behavior is identical to E005: default Hugging Face loading,
with discovered backbone commit and tokenizer configuration recorded per fold.
E005 does not enforce a pinned revision; E008 introduces no revision override.
The inherited `config.json` and fold result configuration describe the unchanged
E005 training protocol. `resolved_config.json` identifies E008, its population
criterion, inherited protocol, and OOF-only gate. Runtime/model metadata,
truncation counts, hashes, epochs and selected checkpoints follow E005 conventions.
Diagnostic training RMSE uses E005's pooled selected-model training predictions
(each retained sample appears in four fold training partitions).

## Fair comparison and diagnostics

The canonical E005 OOF CSV is required before training. E008 checks its canonical
identities, labels, folds and predictions, then restricts it to `label > 0.0`.
Both experiments must have exactly 732 matched filenames with identical labels
and folds. Metrics are computed from the actual artifact, not hard-coded.
Supplied approximate E005 regular-population reference values are RMSE 0.645118
and Pearson 0.792181; the all-769 RMSE is not the comparison baseline.

Reports contain pooled and per-fold n, RMSE, Pearson, selected E008 epochs,
E008-minus-E005 deltas, relative RMSE change percent, and counts of folds
improving RMSE, Pearson or both (out of five). Negative RMSE delta and positive
Pearson delta mean improvement. A zero baseline RMSE makes the relative change
undefined (JSON null). Undefined Pearson is also JSON null.

Diagnostics include prediction/residual Pearson correlations; low (0<label<3),
mid (3<=label<4), high (4<=label<=5) target groups with counts, RMSE comparisons
and mean predictions; and 20 largest improvements/deteriorations ranked by
`e005_abs_error - e008_abs_error`. These groups cover all allowed positive scores,
including values between half-point boundaries. Empty groups retain count zero.
Reports produce statistics without generating conclusions.

## Commands

Local checks, from the repository root:

```sh
.venv/bin/pytest
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Kaggle prerequisites follow [E005](E005.md): GPU enabled, repository installed
with `pip install --no-deps -e /kaggle/working/grammar-scoring`, CUDA PyTorch,
Transformers, sentencepiece, protobuf, and project scientific dependencies.
Make the canonical train metadata, raw transcripts, frozen folds and E005 OOF
available as input datasets. Replace the input dataset mount names below with
those in your notebook; `GRAMMAR_DATA_DIR` must contain `Dataset_Final/train.csv`.

Bounded smoke test (32 training / 16 validation positive rows from frozen fold 0,
two successful optimizer updates, save/reload, no canonical OOF output):

```sh
GRAMMAR_DATA_DIR=/kaggle/input/your-competition-data \
python /kaggle/working/grammar-scoring/scripts/run_deberta_no_zero.py \
  --transcript-dir /kaggle/input/your-canonical-artifacts/transcripts \
  --fold-path /kaggle/input/your-canonical-artifacts/features/train_folds.csv \
  --e005-oof /kaggle/input/your-e005-artifacts/oof/E005_deberta_finetuned.csv \
  --artifact-dir /kaggle/working/artifacts --smoke
```

Full training and OOF evaluation:

```sh
GRAMMAR_DATA_DIR=/kaggle/input/your-competition-data \
python /kaggle/working/grammar-scoring/scripts/run_deberta_no_zero.py \
  --transcript-dir /kaggle/input/your-canonical-artifacts/transcripts \
  --fold-path /kaggle/input/your-canonical-artifacts/features/train_folds.csv \
  --e005-oof /kaggle/input/your-e005-artifacts/oof/E005_deberta_finetuned.csv \
  --artifact-dir /kaggle/working/artifacts --resume
```

Resume verifies complete fold artifacts using the inherited protocol/input hash,
checkpoint checksums, history and partition predictions. Existing incomplete
fold directories fail loudly; rerun without `--resume` to retrain. No training
hyperparameter switches are exposed. GPU execution has not been performed as
part of implementation; E008 results are pending.

## Artifacts and submission gate

Under the chosen artifact root:

- `oof/E008_deberta_no_zero_block.csv`: exactly 732 rows; filename, label, fold,

- `models/E008/fold_0/best.pt` through `models/E008/fold_4/best.pt`, alongside
  `history.json` and `result.json` (training/validation predictions and metadata).
- `experiments/E008/`: `config.json`, `resolved_config.json`, `population.json`,
  `training_history.json`, `fold_metrics.json`, `summary.json`,
  `e005_comparison.json`, `fold_comparison.csv`, `score_groups.csv`,
  `paired_errors.csv`, `largest_improvements.csv`, `largest_deteriorations.csv`.

Training stops after OOF diagnostics for manual review. There is no test
inference, submission generation, blending or submission in this implementation.
Generated artifacts stay gitignored and must not be committed.
