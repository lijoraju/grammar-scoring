# E007: supervised ordinal DeBERTa

E007 isolates an ordinal BCE objective against E005 continuous MSE. E005 files
and artifacts are unchanged. CUDA smoke and full training are pending separate
Kaggle T4 execution; there are no E007 performance results yet.

The backbone, raw Whisper text, masked mean pooling, dropout, frozen folds,
five epochs, optimizer, accumulation, scheduler, seed and checkpoint selection
match E005. Each fold reloads original pretrained weights. No acoustic features,
test data, ensembling, calibration, or submission generation are involved.

The shared bias-free latent layer gives s(x). Thresholds are parameterized as
`theta_0 = a`, `theta_k = a + sum(softplus(delta_i), i=1..k)`. Logits are
`s(x) - theta_k`, so `P(y > SCORE_VALUES[k])` decreases by construction.
Initial thresholds are -2, -1.5, ..., 2; increments start at 0.5. The free
threshold origin replaces a redundant latent intercept. Threshold arithmetic
and BCE use FP32 within CUDA FP16 autocast. Backbone weights remain FP32 and
fully trainable. Configuration records vocabulary and threshold initialization.

Targets use the exact ten observed score values, with nine targets
`1[y > SCORE_VALUES[k]]`. Loss is unweighted mean BCE across rows and thresholds.
Class probabilities are successive cumulative differences, with endpoint masses
`1-q_0` and `q_8`. Prediction is their score-weighted expectation. Probability
validation checks finiteness, monotonicity, nonnegativity and unit row sums;
there is no sorting, rounding, clipping or rescaling.

## Kaggle T4 commands

Use the same environment and canonical input mounts as E005. Enable a Tesla T4
GPU and provide the original Hugging Face model/tokenizer through Internet or
cache. From the repository root, install using the existing pattern:

```sh
pip install -e . --no-deps
```

Set these paths to the mounted inputs before imports. `GRAMMAR_DATA_DIR` must
contain `Dataset_Final/train.csv`. `E007_INPUT_ARTIFACTS` contains the canonical
train transcripts, frozen folds and E005 OOF CSV. Outputs go to writable storage.

```sh
export GRAMMAR_DATA_DIR=/kaggle/input/your-competition-data
export GRAMMAR_ARTIFACT_DIR=/kaggle/working/artifacts
export E007_INPUT_ARTIFACTS=/kaggle/input/your-canonical-artifacts
```

First run the real CUDA smoke check:

```sh
python scripts/smoke_test_deberta_ordinal.py \
  --transcript-dir "$E007_INPUT_ARTIFACTS/transcripts" \
  --fold-path "$E007_INPUT_ARTIFACTS/features/train_folds.csv" \
  --smoke-dir "$GRAMMAR_ARTIFACT_DIR/smoke/E007"
```

Only after smoke PASS, run all five frozen folds:

```sh
python scripts/run_deberta_ordinal.py \
  --transcript-dir "$E007_INPUT_ARTIFACTS/transcripts" \
  --fold-path "$E007_INPUT_ARTIFACTS/features/train_folds.csv" \
  --e005-oof-path "$E007_INPUT_ARTIFACTS/oof/E005_deberta_finetuned.csv" \
  --artifact-dir "$GRAMMAR_ARTIFACT_DIR" --device cuda --resume
```

Smoke stops after two genuine AMP optimizer updates or fails after sixteen
attempts; skipped steps do not advance the scheduler. It checks real-model
shapes [batch,9], cumulative targets, masked pooling, dtype, backward, memory,
checkpoint round trip and valid bounded expectations. Smoke artifacts are
isolated under `smoke/E007/run-*`, with no canonical experiment results.
Tokenization reports lengths before truncation and actual padded lengths;
expected truncation above 256 is diagnostic, never grounds to change protocol.

Resume validates configuration/input identity, checkpoint hash, complete epoch
history, selected epoch, partition identities and probability decoding.
Incomplete fold directories fail clearly. Repair a fold with `--fold N` without
`--resume`, then run the full command with `--resume`. Partial runs do not write
pooled metrics. The baseline OOF file is validated before a full run and its
hash is recorded. Keep downloaded completed folds under the same output paths
when resuming in a new Kaggle session.

## Outputs after full training

- `models/E007/fold_0/best.pt` through `fold_4/best.pt`, with history and recovery
  metadata per fold, including GPU peak allocated bytes.
- `oof/E007_deberta_ordinal.csv`: exactly the established six columns, canonical
  row order, residual defined as target minus prediction.
- `experiments/E007/config.json`, `training_history.json`, `fold_metrics.json`,
  and `summary.json`: selected epochs, fold/pooled RMSE and Pearson, comparable
  pooled training RMSE, E005 deltas and counts of improving folds, prediction
  and residual correlations, runtime, hashes and memory.
- `score_level_comparison.csv`: both experiments, count, population prediction
  standard deviation, mean/min/max, prediction-minus-target signed error,
  MAE and RMSE. Focus on scores 0, 2, 3, 4 and 5. Scores 1 and 1.5 have only
  one and three rows and do not support strong conclusions.
- `score_group_comparison.csv`: LOW (<=2), MID (2.5..4), HIGH (>=4.5), including
  n, RMSE, MAE, mean prediction, mean target and mean signed error.
- `ordinal_diagnostics.json`: every-row validity and prediction min/max/mean/std.
- `cumulative_oof.csv`: separate identified cumulative probabilities in canonical
  order; the canonical OOF schema stays unchanged.

Diagnostic training predictions come from each fold's selected checkpoint on
its training partition, so each train row occurs four times, matching E005.
All generated artifacts remain ignored. No new dependencies were introduced.
No commit, test predictions, leaderboard tuning or submission is part of E007.
