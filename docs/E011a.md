# E011a: cross-fitted DeBERTa + frozen WavLM representation fusion

The hypothesis is that complementary audio information improves grammar scoring
when fused with fine-tuned text representations. Supplied motivating observations
are E008 RMSE 0.619789 / Pearson 0.794231 and E009 RMSE 0.899787 /
Pearson 0.642864. Their prediction correlation was 0.609580, residual correlation
0.347504, and audio had lower absolute error on 276/732 (37.70%) samples.
E010 did not justify full alternative-ASR transcription. These observations are
references, not newly measured E011a results.

The protocol retains exactly the E008 732 positive-label rows in canonical input
order and preserves existing folds. It never filters by filename IDs. For a row
in fold k, only E008 fold-k best.pt supplies its text representation. The existing
E008 completion validator verifies the selected checkpoint checksum, protocol,
input identity, training and validation partitions and selection history. Each
checkpoint requires its original result.json and history.json alongside best.pt.
This guards against mislabeled checkpoint paths as well as incorrect row mapping.

The encoder architecture is constructed from the configuration recorded in
E008 result.json, using the existing DebertaRegressor and strict checkpoint loader.
No original pretrained encoder weights are used. Checkpoints are plain complete
state dictionaries with backbone, dropout and regression head keys. Extraction
bypasses the dropout and head, using final hidden-state masked mean pooling without
normalization, float32, eval, no_grad, seed 42 and deterministic Torch algorithms.
The tokenizer uses the E008 model identity and recorded backbone revision,
max_length 256, truncation and dynamic padding. E008 did not separately pin a
tokenizer revision: compatibility assumes its tokenizer corresponds to that
recorded model revision. Tokenizer configuration is retained in cache provenance.

Text caches require all three artifacts, semantic configuration equality,
fingerprint equality, file checksums, correct shape, finite values, exact ordered
filenames/labels/folds, and fold == checkpoint_fold. The fingerprint includes
transcripts, population, tokenizer/model, pooling, length and checkpoint metadata
and hashes. Runtime batch size does not invalidate reuse. All E008 fold metadata
and checkpoints remain required even for cache-only runs, to verify provenance.
Partial, corrupt or incompatible caches fail closed; there is no overwrite option.

Audio uses existing E009 embeddings only, aligns by filename, and validates exact
one-to-one population, labels, folds, 768 dimensions and finite values. No audio
extraction runs. E009 extraction metadata is recorded when available; source
embedding and metadata hashes are always recorded.

Three controls use raw Ridge(alpha=1.0) predictions: text, audio and concatenated
fusion. Every fold fits independent StandardScalers using its training rows only;
fusion concatenates scaled text and audio into 1536 features. There is no search,
clipping, calibration, weighting, dimensionality reduction or target transform.
This follows the requested single cross-fitting protocol. It is not nested encoder
cross-validation: downstream training representations from other encoder folds
can depend on labels in the downstream validation fold. This limitation matters
when interpreting the resulting OOF estimate; the protocol is left unchanged.

All models report pooled and per-fold RMSE/Pearson. Fusion compares against actual
filename-aligned E008 OOF, including metric deltas (fusion minus E008), improving
fold counts, prediction/residual correlations and lower-absolute-error count and
percentage. Fixed true-label bands are low <3, mid 3<=label<4, high >=4; each
reports count, paired metrics and mean predictions. Undefined correlations become
JSON null. An absolute audio-control metric deviation >0.01 from either supplied
E009 reference prints a warning and is recorded, without changing the pipeline.

Continuation requires meaningful improvement over E008, not merely text Ridge.
A compelling guideline is fusion RMSE <=0.59, Pearson >= E008 Pearson and RMSE
improvement in at least four folds. This is an external decision guideline, never
an automatic experiment branch. There is no test inference or submission.

## Kaggle command

Use the same optional CUDA Torch, Transformers, sentencepiece and protobuf runtime
as E008; no new dependencies are introduced. Install the repository with
`pip install --no-deps -e /kaggle/working/grammar-scoring`. Replace input dataset
mount names with actual mounts. Competition data must contain Dataset_Final/train.csv.

```sh
GRAMMAR_DATA_DIR=/kaggle/input/your-competition-data \
python /kaggle/working/grammar-scoring/scripts/run_multimodal_fusion.py \
  --transcript-dir /kaggle/input/your-canonical-artifacts/transcripts \
  --fold-path /kaggle/input/your-canonical-artifacts/features/train_folds.csv \
  --e008-model-dir /kaggle/input/your-e008-artifacts/models/E008 \
  --e008-oof /kaggle/input/your-e008-artifacts/oof/E008_deberta_no_zero_block.csv \
  --audio-dir /kaggle/input/your-e009-artifacts/embeddings/E009 \
  --artifact-dir /kaggle/working/artifacts --device cuda --batch-size 8
```

Rerunning reuses a validated cache automatically. Add `--cache-only` to prohibit
extraction, or `--extract-only` to extract/validate text without downstream fitting.
`--text-cache-dir` accepts an existing cache on another mount. Defaults honor
GRAMMAR_ARTIFACT_DIR and the existing path abstraction.

Under the output artifact root:

- embeddings/E011a/: text_embeddings.npy (732,768), text_metadata.csv with
  filename/label/fold/checkpoint_fold, extraction.json.
- oof/: E011a_text.csv, E011a_audio.csv, E011a_fusion.csv with
  filename/label/fold/prediction/residual/abs_error.
- experiments/E011a/: config.json, metrics.json, diagnostics.json with full
  provenance, cache validation, audio sanity checks and raw comparisons/bands.

Generated artifacts remain ignored. E008/E009 sources are read-only inputs.
Real-artifact extraction and experiment metrics have not been run locally.

Local compatibility: installed Torch emits a NumPy 2 ABI initialization warning.
Real extraction requires a compatible Torch/NumPy pair for Tensor.numpy(). The
fake-model test uses a list conversion seam to exercise extraction offline;
production extraction does not bypass or conceal this runtime incompatibility.
