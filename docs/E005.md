# E005: canonical supervised DeBERTa fine-tuning

E005 compares task-specific fine-tuning with E003b's frozen DeBERTa + Ridge
baseline (OOF RMSE 0.909674, Pearson 0.705234). E005 is completed. Its verified
OOF RMSE is 0.8352476523 and OOF Pearson is 0.7419439817; diagnostic train
RMSE is 0.6138006888. Selected fold epochs are [3, 4, 5, 2, 2], and the public
leaderboard score is 0.3998. E008 remains the selected final model. No E006
work is included.

The architecture is fully trainable `microsoft/deberta-v3-base` AutoModel,
final hidden states, attention-mask mean pooling, dropout 0.1, and a single
linear regression output. Raw Whisper text is unchanged. Tokenization uses
256 tokens, truncation, and padding dynamically within each batch. Token-length
counts are diagnostic and never change the maximum length.

`CONFIG` in `grammar_scoring.experiments.deberta_finetuning` is the frozen
protocol: MSE, AdamW, learning rate 2e-5, weight decay 0.01, five epochs, batch
size 8, accumulation 2 (effective batch 16), linear scheduler, warmup ratio
0.10, gradient clipping 1.0, CUDA FP16, and seed 42. Warmup optimizer steps
are `ceil(total_optimizer_steps * 0.10)`. There are no CLI hyperparameter
switches. Checkpoint selection minimizes validation RMSE; ties retain the
first epoch. Every fold starts from original pretrained weights and runs all
five epochs. CUDA OOM stops the run without changing batch size.

Labels, transcripts and persisted folds join by filename in canonical train
CSV order. Validation requires 769 unique train identities, nonempty raw text,
finite scores in [0, 5], and frozen folds with sizes 154/154/154/154/153.
No test CSV, test transcript, embeddings, linguistic or audio features are read.

Loss history is the sample-weighted mean of mini-batch MSE observed during
training before each update. Accumulation weights each mini-batch by its share
of the accumulation group's samples. This includes a final partial group.
Optimizer steps per epoch are `ceil(number_of_batches / 2)`; the scheduler
advances on successful optimizer updates, including the final partial group.
AMP overflow skips both the update and its scheduler step. Diagnostic training
RMSE pools predictions on each selected model's training partition; each
sample therefore occurs four times, unlike the exactly-once OOF predictions.

## Kaggle GPU execution

Use a dedicated GPU notebook with CUDA PyTorch, `transformers`, `sentencepiece`,
`protobuf`, and the project's NumPy/pandas/scikit-learn/SciPy runtime. Install
missing tokenizer packages as needed; the implementation does not add heavy ML
packages to `pyproject.toml`. The local Intel macOS PyTorch 2.2 runtime uses an
AMP scaler compatibility fallback; current CUDA runtimes use `torch.amp`.
Access to Hugging Face is needed for the original model and tokenizer on first
execution (or provide their complete standard Hugging Face cache offline).
Enable Kaggle Internet if installing packages or fetching model weights.

Install project code with `pip install --no-deps -e /kaggle/working/grammar-scoring`
after making the repository available. Set `GRAMMAR_DATA_DIR` and
`GRAMMAR_ARTIFACT_DIR` **before importing** project modules. The data directory
must contain `Dataset_Final/train.csv`; the input artifact directory contains
`transcripts/train.jsonl` and `features/train_folds.csv`. Output must point to a
writable directory. The existing loader reads only the train labels.

Suggested notebook cells for reproducing the completed experiment:

```python
import os
from pathlib import Path

os.environ["GRAMMAR_DATA_DIR"] = "/kaggle/input/your-competition-data"
os.environ["GRAMMAR_ARTIFACT_DIR"] = "/kaggle/working/artifacts"
input_artifacts = Path("/kaggle/input/your-canonical-artifacts")
output_artifacts = Path(os.environ["GRAMMAR_ARTIFACT_DIR"])
```

```python
import json
from dataclasses import asdict
import torch
from grammar_scoring.experiments.deberta_finetuning import (
    CONFIG,
    load_inputs,
    runtime_info,
    run_experiment,

    input_artifacts / "transcripts",
```

```python

```

For a first run, `resume=True` also works when fold directories do not exist.
For recovery, first restore the saved fold directories from the previous Kaggle
output into the writable artifact directory. A directory that exists but is
incomplete causes a clear error; use a non-resume single-fold run to rerun it.
There is no mid-epoch recovery.

```python
import pandas as pd

experiment = output_artifacts / "experiments/E005"
display(pd.read_json(experiment / "training_history.json"))
display(pd.read_json(experiment / "fold_metrics.json"))

```

CLI equivalent:

```sh
python scripts/run_deberta_finetuning.py \
  --transcript-dir /kaggle/input/your-canonical-artifacts/transcripts \
  --fold-path /kaggle/input/your-canonical-artifacts/features/train_folds.csv \
```

`--fold 0` runs just one canonical fold and saves its checkpoint/history/result;
it does not replace full experiment OOF or summary artifacts. After repairing
an incomplete fold, run all folds with `--resume` to assemble the full reports.

## Artifacts and recovery

- `models/E005/fold_N/best.pt`: only the selected model state, including head.
- `models/E005/fold_N/history.json`: each epoch's history, including incomplete
  run progress for inspection.
- `models/E005/fold_N/result.json`: completion marker, selected epoch/metrics,
  all history, identified validation and training predictions, runtime and
  model/tokenizer metadata, protocol/input identity and checkpoint checksum.
- `experiments/E005/config.json`: exact canonical configuration.
- `experiments/E005/training_history.json`: all 25 epoch records.
- `experiments/E005/fold_metrics.json`: selected metrics and sizes per fold.
- `experiments/E005/summary.json`: OOF metrics, pooled diagnostic training RMSE,
  per-fold selected results, runtime/model details and token-length diagnostics.
- `oof/E005_deberta_finetuned.csv`: established six-column OOF schema with raw
  continuous predictions in canonical filename order.

Resume verifies configuration and aligned-input hashes, checkpoint checksum,
complete epoch history, best epoch selection, partition identities/labels/folds,
finite predictions and selected metrics. Corrupt/incomplete/mismatched folds
fail rather than being skipped. No state from another fold initializes training.
Runtime and discovered pretrained commit information are recorded per fold.
Seeds and practical deterministic kernels do not guarantee identical results
across hardware/software stacks. Undefined Pearson is serialized as JSON null.
All generated artifacts remain gitignored; do not commit outputs or weights.

## Offline tests

Install PyTorch in the test environment to execute model/training tests. They
need neither Transformers, GPU nor pretrained model downloads: tests inject
lightweight backbones and a fake Hugging Face surface. Without PyTorch, the
heavy tests skip explicitly; input, OOF and resume-validation tests still run.
Run `uv run pytest`, `uv run ruff check .`, and `uv run ruff format --check .`.
